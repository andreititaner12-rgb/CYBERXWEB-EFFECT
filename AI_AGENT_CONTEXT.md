## ⚡ Правила производительности рендеринга (аудит 2026-09, v2)

1. **Никаких blur-фильтров для ambient-свечений** — только `radial-gradient` (0% GPU blur cost).
2. **Трансформации 3D-наклона карточек — rAF-троттлинг, без CSS-transition во время движения** (переход включается только на выходе). Реализация: `src/components/ui/ThreeDCard.tsx`.
3. **Никаких `backdrop-filter` внутри `preserve-3d`** и никаких фильтров на соседних карточках при ховере.
4. **WebGL (Mouse3DViewer) рендерит только в зоне видимости** (IntersectionObserver) + полный dispose при анмаунте.
5. **Один источник плавного скролла — Lenis** через `src/utils/smoothScroll.ts` (`smoothScrollTo`); нативный `scrollIntoView({behavior:'smooth'})` и CSS `scroll-behavior: smooth` конфликтуют с Lenis (рывки, зависания).
6. **Никаких CSS-фильтров на полноэкранном видео** (brightness/contrast) — вместо них затемняющий overlay-слой.
7. **Параллакс фона — только transform на МАЛЕНЬКИХ (≤55vw) слоях в потоке документа**; никаких фиксированных анимируемых слоёв на всю страницу и никаких постоянных анимаций под backdrop-filter карточками (бесконечный resample).
8. Фирменный шрифт **Tactic Sans**: `@font-face` в `src/index.css`, файлы в `/public/fonts/`.
### Правила плавных смен контента (v2.1)

10. **Смена блока обзора клуба** — чистый CSS (`cyberx-deepdive` keyframes в `index.css`): затухание -> подмена контента -> въезд. НЕ оборачивать этот блок в `AnimatePresence`/exit-анимации framer — exit-клон большого блока + `backdrop-filter` перегружают растеризацию.
11. **`backdrop-filter` запрещён на больших (~экранных) блоках**, которые перемонтируются или анимируются (у deep-dive он отключен классом `.cyberx-deepdive.glass-card`).
12. **Галерея клуба рендерит только текущее + затухающее фото** (`galleryIndex` / `prevGalleryIndex`), а не весь стек из 8-10 фото.
13. **Движущаяся обводка акций** — framer `layoutId="promoHoverGlow"` (общий layout-элемент переезжает между карточками). Аналогичный паттерн применим для любых «переезжающих» подсветок.
### Правила загрузки ресурсов (v2.2 — оптимизация)

14. **Code-splitting тяжёлых библиотек**: three.js (649KB) и Leaflet (168KB) грузятся через `React.lazy` + `LazyMount` — главный бандл 258KB вместо 1.1MB. Секции «Железо» и «Карта» монтируются только при приближении на 700px.
15. **Якоря навигации (`id="hardware"`, `id="location"`) живут на обёртках LazyMount** — навигация работает ещё до монтирования контента. НЕ возвращать id внутрь ленивых секций (дубликат id + сломанная навигация).
16. **Idle-предзагрузка**: чанки HardwareVisualizer/LocationMapSection импортируются в `requestIdleCallback` — к доскроллу код уже в кэше.
17. **hero-bg.mp4 пережат CRF 26 (19MB -> 8.4MB, PSNR 41.8dB)**, голосовое приветствие WAV -> MP3 96k (706KB -> 49KB). Перекодирование: `ffmpeg -crf 26 -preset slow -an -movflags +faststart`.
18. **Изображения ниже фолда — `loading="lazy" decoding="async"`**.
19. **Хедер: backdrop-blur-md** (не xl) — при фоне 95% визуально неотличимо, вдвое дешевле сэмпл при скролле.
20. **Курсор-прицел: rAF останавливается в покое** (idle-stop) — 0% CPU, когда мышь не двигается.
### Правило вечных анимаций (v2.3 — анти-лаг: «полосы» в полноэкранном режиме)

21. **Бесконечные анимации — ТОЛЬКО compositor-свойства (transform/opacity) на выделенных слоях.** Запрещено анимировать `background-position`, `box-shadow`, `border-color`, `filter` в infinite-циклах: каждый кадр = raster + repaint, на 1920x1080 это валит композитор GPU (рывки, полосы, «осыплется» сайт) — в маленьком окне незаметно, в полноэкранном критично.
22. **Паттерн `badge-gold-shimmer`**: перелив = ::before-полоса (width 400%, left -200%, background-size 50%) с `transform: translateX(0 -> 50%)` внутри `overflow:hidden; isolation:isolate` бейджа. Один период градиента = 200% ширины бейджа — бесшовный цикл, идентичный прежнему background-position 0%->-200%. НЕ возвращать background-position.
23. **`.animate-pulse`/`.animate-ping` promoted через `will-change`** (opacity / transform+opacity) — чтобы их циклы не перерисовывали родительские слои (особенно хедер с backdrop-filter).
24. Диагностика таких лагов: CDP-трейс (`Tracing.start`, категории devtools.timeline). Признак проблемы: `Paint`/`RasterTask` сотни раз за 2.5с при неподвижной мыши. После фикса: Paint ~0, RasterTask ~0, остаются только DrawFrame композитора.
25. Софтверный рендер песочницы рисует кадр ЦЕЛИКОМ при любой анимации (нет damage-tracking) — абсолютные ms DrawFrame там не показатель; смотреть на Paint/RasterTask.
### Правила интерактива (v2.4 — «полосы не уходят до перезагрузки»)

26. **Модалка зон (ZonesShowcase) — ТОЛЬКО CSS-вход/выход** (`animate-zones-overlay-in/out`, `animate-zones-window-in/out` + `isClosing`-таймер 250мс). framer AnimatePresence/motion exit здесь ЗАПРЕЩЁН: exit-клон полноэкранного окна с backdrop-blur-md даёт всплеск композитинга GPU, после которого сайт «сыпется» до перезагрузки. Booking/Tournament/Admin модалки — безопасны (просто animate-fadeIn, без exit-клонов).
27. **Виджеты блока «Железо» монтируются ОДИН РАЗ** и переключаются CSS-скрытием (`hidden` на обёртке, для контейнеров с display-классами — `!hidden`). Условный рендер `{tab === 'x' && <Widget/>}` пересоздавал canvas/WebGL при каждой смене вкладки — трёхмерная мышь = загрузка GLB + новый WebGL-контекст + компиляция шейдеров = «дёргается, будто перезагружается».
28. **Mouse3DViewer: applySize() при показе вкладки** (IO isIntersecting) — при монтировании в скрытом состоянии размер = фолбэк 360x280; также applySize игнорирует 0x0 (display:none), иначе renderer.setSize(0,0) схлопнет канвас. IntersectionObserver-ы виджетов корректно гасят циклы при display:none-предке.
### Правило backdrop-filter (v2.5 — корень «лагает и сыпется после зон»)

29. **КОРНЕВАЯ ПРИЧИНА бага «весь остаток сайта лагает и сыпется, начиная с середины блока ЗОН»**: при доскролле до середины зон срабатывает LazyMount секции «Железо» (rootMargin 700px), а у неё 5 glass-card с `backdrop-filter: blur(14px)` — и эти блюр-слои, даже ЗА ЭКРАНОМ, не отбрасываются композитором и форсируют обработку фона каждый кадр (+103 мс/кадр в 1080p: 177→74 мс при выключении). Симптом на реальном слабом GPU: полосы, артефакты, перманентные лаги до перезагрузки.
30. **Правило: backdrop-filter только у элементов, которые (а) реально в кадре, (б) на полупрозрачном фоне (<85%), где блюр виден.** Карточки на фоне 85–95% непрозрачности — блюр отключён (`#hardware .glass-card, #location .glass-card { backdrop-filter: none }` в index.css). НЕ добавлять glass-card/glass-panel в длинные ленивые секции без проверки.
31. **Диагностика перманентных лагов**: бисекция DOM вживую (`el.remove()` + замер rAF-интервалов) + CDP-трейс. Признак: main-поток пуст (FunctionCall ~0.1мс), Paint ~0, но DrawFrame раздут → виноваты слои композитора (backdrop-filter/огромные слои), не JS.
### Урок сравнения с рабочей старой версией (v2.6 — CyberX11111ANIM из архива пользователя)

32. **Пользовательский эталон** (CyberX11111ANIM, работает на его GPU без крахов): те же glass-card с blur(14px) в железе (51 backdrop-filter элемент на странице!), тот же hero-bg.mp4 19MB, тот же framer AnimatePresence в модалке зон. НО: фоновые слои статичны (3 blur-орба без анимации) и виджеты железа монтируются УСЛОВНО ({tab && <Widget/>}) — WebGL-контекст мыши создаётся ТОЛЬКО при открытии вкладки «Мыши».
33. **Вывод: связка «WebGL-контекст + блюр-карточки + многослойный фон», созданная ОДНОВРЕМЕННО при монтировании железа (середина зон!), роняла драйвер слабого GPU** — отсюда «лагает и сыпется весь остаток сайта до перезагрузки». Каждый элемент по отдельности (как в старой версии) — переносится нормально.
34. **Решение Mouse3DViewer — ленивая активация `activated`**: триггер-IntersectionObserver включает тяжёлый init ТОЛЬКО при первом реальном показе (вкладка «Мыши» открыта И в вьюпорте). Дальше контекст живёт — повторные показы мгновенны. НЕ возвращать создание WebGL в монтирование и НЕ пересоздавать на каждую смену вкладок.
35. 2D-виджеты железа (симулятор герцовки и т.п.) живут постоянно с IO-гейтингом — это дёшево и убирает «дёргания» при переключении вкладок.
36. A/B-замер в точке сбоя (середина зон): новая 49 мс vs старая 108 мс (в софтверном рендере; у старой в этом месте в кадре glass-карточки зон с блюром).
### Правила карты и галерей (v2.7)

37. **Dynamic2GisMap: НЕТ flyTo при монтировании** (isFirstRunRef). Карта монтируется лениво (LazyMount #location, rootMargin 1100px — раньше дефолтных 700px, тайлы успевают осесть) — анимированный полёт камеры в этот момент давал разрывы/артефакты на GPU. flyTo только по действию пользователя (смена клуба).
38. **Внутри .leaflet-container промоушен will-change ЗАПРЕЩЁН** (`.leaflet-container .animate-pulse/.animate-ping { will-change: auto }`): маркеры-слои поверх трансформирующихся тайл-панелей = артефакты. Маленькие маркеры дешевле перерисовывать.
39. **LazyMount имеет проп rootMargin** (дефолт '700px 0px'); для карты — '1100px 0px'.
40. **Галерея обзора клуба: в DOM только активное + предыдущее фото** (8-10 фото сразу = спайк растеризации), ВХОД нового фото — CSS-АНИМАЦИЯМИ `galleryPhotoIn` (проявление) + `galleryKenBurns` (зум 6с): в отличие от transition, анимации играют при монтировании. Это паритет с эффектом галереи «Зоны».
41. **SoundController.now() = currentTime + 30мс** для ВСЕХ событий: suspended-контекст заморожен, события «в прошлом» после resume не играют (баг «первый клик без звука»). Громкости: hover 0.03, click 0.06.
### Звук и карта (v2.8)

42. **Прелоудер БЕЗ синтезированных звуков**: playDataPacket/playSystemReady не вызываются (пользователь просил убрать «пик-пик»). Первый звук после входа — женское приветствие + фоновый трек.
43. **hero-intro.mp3** (2.72с, 130 BPM, биты каждые 0.46с: 0.06/0.52/0.98/1.44/1.90/2.36) играет при раскрытии hero (volume 0.55, под приветствие). ВСЕ появления навигации синхронизированы с битами: звук playNavAppear(idx) на beats[idx], визуальный delay кнопок = тот же массив, разделители на 0.29+idx*0.46, капсула на 2.36. Менять тайминги только парами (звук+визуал).
44. **Клики = /audio/ui-click.mp3** (сэмпл 0.13с, gain 0.5, BufferSource; фолбэк на синтезированный клик пока mp3 не догрузился). Сэмпл декодируется один раз в loadClickSample() при первом init().
45. **КАРТА (самостоятельная работа, не по старому образцу)**: корень разрывов = 8+ backdrop-blur оверлеев ПОВЕРХ живых тайлов (метки, бар, кнопки зума) — каждое движение = пересэмплинг блюра сквозь тайлы. Лечение: `#location .backdrop-blur*` и `.leaflet-container .backdrop-blur*` => backdrop-filter:none (фоны плашек 90-95% непрозрачны, визуально неотличимо). Плюс: тайлы keepBuffer 8 -> 1 (в разы меньше запасных текстур), flyTo/flyToBounds 1.3/1.2с -> 0.85с, монтирование за 1100px, flyTo нет на первом прогоне.
46. Правило: **живая карта/видео + backdrop-blur над ними = запрещённая комбинация**. Оверлеи над живыми слоями — только на непрозрачных фонах.
### Звуковая политика (v2.9 — финальная, по просьбе пользователя)

47. **Звуковой набор = как ДО правок агента**: синтезированные тихие клики (playClick, triangle 320->140Hz, громкость 0.04), тихие playNavAppear/playCapsuleAppear/playTrigger (0.03/0.035/0.03). Никаких mp3-сэмплов кликов, никаких треков загрузки/раскрытия. Из файлов в public/audio только: cs2-footsteps.mp3 (тестер звука в железе), welcome-cyberx-female.mp3 (+male welcome-cyberx.mp3).
48. **playHover() = no-op («тишина»)** — звук наведения вырезан по просьбе («пик такой вырежи»). Метод сохранён как заглушка, вызовы не трогать.
49. **Прелоадер беззвучен полностью** (playDataPacket/playSystemReady не вызываются).
50. **Осталось из правок звука**: только now() = currentTime+30мс (фикс «первый клик без звука», на характер звука не влияет) — НЕ откатывать.
